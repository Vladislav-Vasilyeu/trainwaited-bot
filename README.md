# TrainWaited

Telegram-бот для отслеживания билетов Белорусской железной дороги на `pass.rw.by`. Бот работает через long polling и Playwright, входящие HTTP-запросы ему не нужны — на сервере должен постоянно работать один процесс.

## Отслеживание мест

Создайте подписку, выбрав маршрут, дату и поезд. Доступны варианты:

- Любые билеты, любые места в плацкарте или любые места в купе.
- В плацкарте: нижние, верхние, нижние боковые, верхние боковые, любые нижние, любые верхние или любые боковые места.

Категории мест считываются со страницы вагона на сайте БЖД. Наличие может измениться до перехода по ссылке покупки; бот не резервирует и не покупает билеты.

## Запуск через Docker Compose

1. Создайте Telegram-бота через BotFather и скопируйте токен.
2. Скопируйте `.env.example` в `.env` и укажите `BOT_TOKEN`.
3. Запустите бота:

   ```powershell
   Copy-Item .env.example .env
   docker compose up -d --build
   ```

4. Просматривайте логи командой `docker compose logs -f trainwaited-bot`.

Подписки хранятся в постоянном Docker volume. Запускайте ровно один экземпляр: текущее JSON-хранилище рассчитано на один процесс, а не на параллельную запись нескольких реплик. Перед обновлением сохраните файл командой `docker compose cp trainwaited-bot:/app/data/subscriptions.json .\subscriptions-backup.json`. Для восстановления скопируйте его обратно: `docker compose cp .\subscriptions-backup.json trainwaited-bot:/app/data/subscriptions.json`, затем перезапустите контейнер.

Если обновляетесь со старой Compose-конфигурации, где подписки лежали в `.\data\subscriptions.json`, сохраните этот файл до первого запуска новой конфигурации. Запустите новый контейнер, скопируйте резервную копию командой `docker compose cp .\data\subscriptions.json trainwaited-bot:/app/data/subscriptions.json` и перезапустите бота. Не запускайте `docker compose down -v`, если не хотите удалить постоянный volume.

## Деплой без платы за хостинг

Самый простой бесплатный вариант — Docker на уже работающем домашнем компьютере или сервере с доступом в интернет. Перед использованием бесплатного облачного тарифа проверьте актуальные условия, доступность региона, политику остановки простаивающих приложений и необходимость привязки банковской карты: бесплатные тарифы меняются и не всегда гарантируют постоянную работу. Если платформа «усыпляет» фоновые процессы, бот не сможет проверять билеты.

Боту нужен исходящий HTTPS-доступ к Telegram и `pass.rw.by`; открывать порт в интернет не требуется. Храните `BOT_TOKEN` в секретах или переменных окружения сервера, а не в Git. Используйте постоянное хранилище Docker и запускайте только одну реплику.

## Настройки

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `BOT_TOKEN` | — | Обязательный токен Telegram-бота |
| `CHECK_INTERVAL` | `60` | Интервал фоновой проверки в секундах (минимум 10) |
| `SUBSCRIPTIONS_FILE` | `subscriptions.json` | Путь к файлу подписок |
| `MAX_CONCURRENT_CHECKS` | `2` | Максимум параллельных проверок сайта БЖД |
| `CACHE_TTL` | `45` | Время хранения результатов в кэше, секунды |
| `HEADLESS` | `true` | Запуск браузера без окна |
| `BROWSER` | `firefox` | Браузер Playwright: Firefox (и в Docker, и локально) или Chromium |

## Эксплуатация

- Обработка Telegram-обновлений и проверки через браузер асинхронные. Первичная проверка запускается после подтверждения подписки; повторяющиеся проверки не накладываются друг на друга.
- При штатной остановке ресурсы браузера закрываются. Docker перезапустит остановленный контейнер.
- Для платформ, использующих `Procfile`, отдельно установите системные зависимости и браузер Playwright; готовая Docker-конфигурация уже содержит Chromium.
- Сайт БЖД — внешняя зависимость; после изменения его HTML-разметки разбор данных может временно перестать работать. Проверяйте логи после изменений на стороне сайта.
- JSON подходит для одного небольшого экземпляра. Перед масштабированием на несколько реплик или ростом нагрузки перенесите данные в SQLite/PostgreSQL и добавьте процедуры миграции, резервного копирования и мониторинга.
